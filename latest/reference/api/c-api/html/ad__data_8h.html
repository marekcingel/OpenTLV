Validates AD structures and trailing zero padding.

Uses the generic reader with the strict Bluetooth LTV format. A zero byte at a structure boundary starts padding; every remaining byte must be zero. Zero bytes inside a structure remain part of that structure. Unknown types and empty values are accepted. No schema or value-codec validation occurs. Empty input and all-zero input succeed with a zero significant size.

The significant prefix can be passed to a generic reader, walker or schema validator with the original input pointer, preserving source offsets. This function never allocates, copies or retains input bytes. Available when OPENTLV_BLUETOOTH is enabled.

Parameters
[in]dataCaller-owned input, unchanged during the call. May be NULL only when size is zero.
[in]sizeInput size in bytes, including padding.
[out]significant_sizeRequired. Receives the prefix size in bytes, excluding padding, only on success.
[out]error_offsetOptional. On failure receives the failing field's offset relative to data, or the first nonzero padding byte. Argument errors report zero. Unchanged on success.
Returns
TLV_OK if all structures and padding are valid.
TLV_ERR_NULL_ARG for a missing required pointer.
TLV_ERR_INVALID_VALUE for a nonzero byte after padding starts.
TLV_ERR_BUFFER_TOO_SHORT for a truncated structure.
Any other generic reader error, propagated unchanged.
Note
significant_size remains unchanged on failure. Output storage must not overlap the input or each other.
