# Repository instructions

## Changelog

When updating `CHANGELOG.md`:

- Document only user-facing or otherwise meaningful changes included in the
  current commit. Do not list implementation details unless they affect users
  of the library or its build and test workflow.
- Add every new section directly below `## [Unreleased]`.
- Add every new entry at the top of its section.
- Use the existing Keep a Changelog categories (`Added`, `Changed`, `Fixed`,
  and so on) and match the file's existing wording and formatting.
- Include the relevant pull-request or issue reference when one is known.
